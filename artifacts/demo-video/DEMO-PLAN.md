# AURA — 80-second judge demo

## Story

The demo proves one idea: accessibility is a relationship between a person and a page, so the interface should adapt to the person.

## Shot order

1. **0–8s — Learn Me**
   - Begin with the real first-launch screen and AURA Guide mascot.
   - Establish that AURA asks about everyday web comfort, not diagnoses.

2. **8–23s — Personalized OOBE**
   - Show an AI-selected question and a user response.
   - Reveal the completed visual, auditory, motor, cognitive, attention, and language support combination.
   - Establish that this profile drives the later page decisions.

3. **23–36s — Scan**
   - Press **Scan this page**.
   - Show the personalized AURA Fit score and its reasons.
   - Keep the automated WCAG evidence visibly separate from the personalized score.

4. **36–60s — Make This Mine**
   - Press **Make This Mine**.
   - Show the immediate local transformation, followed by semantic refinement.
   - Hold on the changed hierarchy and improved score.

5. **60–73s — Talk to AURA**
   - Enter: **Show me the search**.
   - Show AURA bringing the real search control forward.

6. **73–80s — Trust and reversibility**
   - Press **Original**.
   - Show the untouched website returning immediately.

## Recording rules

- Record the real packaged macOS app; no mockups.
- Keep the pointer movement deliberate and slow.
- Cut waits longer than two seconds.
- Never show provider error states or credentials.
- Use captions for the core claims and retain the original site’s identity.
- Do not claim that AURA Fit is a WCAG score or certification.
